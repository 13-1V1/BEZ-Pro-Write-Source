# BEZ Pro Write

Desktop app for Windows and Mac (Tauri 2 + plain TypeScript/Vite, no UI framework) that
walks a beginner through writing an email, memo, letter, cover letter, or short report
using the 7 C's. Full spec: `docs/BUILD_BRIEF.md` (the original plan; some later decisions are
recorded inside it with dates, the rest live in "Decisions" below — where they differ, the
Decisions list and the code win). Current version: 1.3.0.

## The #1 rule
The app never writes or rewrites the user's words. Checks only point at text, never fix it.
Tips, examples, and phrase banks are "locked" (`src/ui/lock.ts`): no select, copy, or drag.
The only auto-filled text is the user's own saved sender profile.

## Commands
- `npm run dev` — Vite on port 1420. Browser test mode: storage falls back to localStorage, `window.bez` is the App instance (handy for driving screens from the browser console).
- `npx tauri dev` — real app window (uses `%APPDATA%\BEZ Pro Write\`).
- `npm test` — all vitest tests. One file: `npx vitest run tests/checks.test.ts`. One test: add `-t "Courteous"`.
- `npx vitest run tests/dump-flags.test.ts --reporter=verbose` — print every flag on the problem sample (for spotting false alarms).
- `npx tsc --noEmit` — type-check (includes `tests/`).
- `(cd src-tauri && cargo test --lib)` — Rust store tests.
- `npx tauri build` — Windows `.msi` in `src-tauri/target/release/bundle/msi/` (MSI only; the NSIS step fails on a cached-tool folder link).
- Mac `.dmg`: GitHub Actions `.github/workflows/mac.yml` on the private repo `13-1V1/bez-pro-write`. Runs on a version tag push (`v*`) or `gh workflow run mac.yml`; download with `gh run download <id> -n BEZ-Pro-Write-mac -D release/mac`. Builds universal (Apple Silicon + Intel), ad-hoc signed, not notarized (user declined the $99 Apple account; first open is System Settings → Privacy & Security → Open Anyway on macOS 15+, right-click → Open on 11–14).
- `npm run build:web` — web version for the BEZ Works site in `dist-web/` (relative paths, served from `play/bez-pro-write/`). Preview the built copy with the `web-build` launch entry (port 1426).
- `node tools/make-notices.mjs` — regenerate `THIRD_PARTY_NOTICES` (shown on the About tab).
- `pwsh tests/tools/snap-window.ps1 -Out x.png` — screenshot the running app window.

**Releasing:** bump the version in `src-tauri/tauri.conf.json`, `package.json`, `package-lock.json` (both root entries), `src-tauri/Cargo.toml`, `src/screens/settings/about.ts`, and "Current version" at the top of this file. `src-tauri/Cargo.lock` updates itself on the next build; commit it before tagging. An MSI with the same version silently skips replacing files on reinstall, so a version bump is required for the upgrade to take.

## Architecture (big picture)
- **Boot** (`src/main.ts`): loads types, prefs, profiles, and word lists in parallel, builds `AppData`, creates `App` with a `Hooks` object that maps each stage (`type`, `topic`, `profile`, `prep`, `write`, `check`, `finish`) to a screen function, then mounts the window chrome.
- **App** (`src/flow/app.ts`): owns the current `Draft` (`src/drafts/model.ts`), rebuilds the step list on every move (`steps.ts`: no topics → no topic screen; 0–1 profiles → no profile screen, and exactly one is auto-used), renders the shell, handles Cmd/Ctrl+Enter navigation, and autosaves every 3 s, plus on window blur/hide and on close (`saveBeforeClosing` in `main.ts` hooks Tauri's close request, which needs `core:window:allow-destroy`; `flush()` waits for any save already running). Only one copy of the app runs at a time (`tauri-plugin-single-instance` in `src-tauri/src/lib.rs`); a second launch focuses the open window. Screens are plain functions `(app, step) => ScreenView` that return a DOM tree built with `h()` (`src/ui/dom.ts`), plus optional `beforeNext`, `middle` button, `side` panel flag. `app.returnTo` lets a 7 C's screen send the user to a write screen and back.
- **Types are data:** `data/types/*.json` plus user files in `<data folder>/types/` (same `id` wins). `src/types/validate.ts` turns bad files into plain-word problems shown in a Home banner. Topic `sectionOverrides` replace only named fields (`merge.ts`). Section `role` (`header`, `greeting`, `body`, `ask`, `closing`, `signature`) — never the name — decides which checks run. Optional section fields: `what`, `prefix`, `gapBefore`, `framework`.
- **Frameworks:** a section with `"framework": "star"` (STAR, BLUF, PREP, Apology, SBI in `data/frameworks.json`) shows one box per part; answers live in `draft.parts[sectionId]` and are joined into `draft.text[sectionId]`, so checks and export only ever read `draft.text`.
- **Checks pipeline:** `src/checks/run.ts` builds a `CheckInput` from the draft (only non-empty, non-skipped sections) → each `<c>.ts` returns `Flag[]` with offsets **relative to its section's text** → `index.ts` dedupes per C and weights (`data/scoring.json`). Flags with `start === end` are whole-piece notes (missing fact, empty Ask); they appear on check screens but don't count toward the style score. `src/ui/highlight.ts` splits overlapping flags into segments showing color + letter badge. Explanations come from `data/checks.json`. The check screens run in `CHECK_ORDER` (`src/checks/cs.ts`): big issues first (Complete, Clear, Coherent, Courteous), then Concise, Concrete, Correct; a practice draft's focus C goes first. `goal.ts` adds a whole-piece Clear note when the Plan's goal isn't in the first two sentences. Adverbs are flagged only next to a word on the editable `weak-verbs` list. A spot the user marks "This one's fine" is stored in `draft.fine` by `flagKey` (check + section + words, so it survives edits elsewhere); `markFine` grays it and it stops counting everywhere.
- **Spelling** is async: Harper runs in a web worker (`src/spell/harper.ts`). One shared cache (`src/spell/cache.ts`) serves both the write-box underlines and the live scores; the scores only ask for a check once typing pauses (`checkWhenIdle`), and `whenSpellUpdates` redraws the side panel and status bar when results land. The cache clears when new reader/profile names are added to Harper's dictionary. Write boxes draw underlines on a mirror layer behind a transparent textarea (`src/ui/editor.ts`); the layer is hidden and skipped while there are no underlines, because rebuilding it per keystroke was the main typing cost on long drafts.
- **Stats** (`src/scores/stats.ts`) is the single source for the side panel, status bar, and Finish scorecard; while typing they redraw ~150 ms after a pause (`onChange` in `main.ts`). Both scores wait for 30 words ("Write a bit more" in the side panel, a dash in the status bar) — readability counts only prose words (header and signature sections excluded), the style score counts all words, so a letter with a long address block can show a style score before readability.
- **Storage** (`src/storage/store.ts`): Tauri commands `store_root` and `store_read/write/list/delete` (`src-tauri/src/store.rs`) rooted at `%APPDATA%\BEZ Pro Write\` (Windows) or `~/Library/Application Support/BEZ Pro Write/` (Mac). Paths that escape the root are refused; writes go to a temp file then rename. Outside Tauri it falls back to localStorage under `bez:`.
- **Export** (`src/export/`): Save As uses the dialog plugin, and the chosen path is auto-added to the fs scope, so the capability file needs only the `fs:allow-write-file` / `fs:allow-write-text-file` permissions and no scope entries. `.docx` is block format for every type (one paragraph per line, Times New Roman 12 pt, 1" margins, US Letter). Copy uses the clipboard plugin.
- **Pages outside the flow** (the 7 C's guide `src/screens/guide.ts`, Practice `src/screens/practice.ts`) open with `app.goPage(render)`; their Back button returns to the draft and step the user left. F1 opens the guide.
- **Version snapshots** (`src/drafts/snapshots.ts`, files in `snapshots/<draft id>.json`, max 20): saved automatically when moving from Write into the 7 C's check and on reaching Finish (`onStep` hook in `main.ts`), or by hand from File. Shown and restorable on Finish (`src/screens/versions.ts`), with a word-by-word "What I changed since" view (`src/drafts/diff.ts`); restoring saves the current version first. Finish also says how many spots the writer cleared since "Before the 7 C's check" (`spotsIn`). `addSnapshot` copies the writing at call time.
- **Progress** (`src/progress/`): reaching Finish records the piece's spots per C, words, and style score in `settings/progress.json` (one record per draft, replaced if finished again). `summarize` compares the last 5 pieces with the 5 before (trends need 3+ earlier pieces) and picks the C with the most spots per 100 words as the focus; Home's "Your progress" panel shows it, and links to the full page, also at Help → Your progress (`src/screens/progress-page.ts`: style line, spots per C, `byType`, every finished piece).
- **Practice** (`data/practice.json`, `src/practice/practice.ts`): 16 made-up situations over 3 levels. A scenario fills in the Plan only (reader, goal, facts, deadline) and sets `draft.practiceId`; the writing starts empty. A level opens after 2 finished pieces at the level below; `recommend` prefers the learner's focus C.
- **Check something I wrote** uses the hidden built-in type `data/types/own.json` (`"hidden": true` keeps it off the type picker), opened from Home straight to its one big box. `src/screens/own-tools.ts` opens a .txt or .docx file (mammoth, loaded only for Word files) and lets the user mark paragraphs as greeting / Ask / closing (`draft.tags`); `src/checks/tagged.ts` turns those into parts for the checks (other paragraphs blanked to spaces so offsets still match the box) and `backToBox` points the flags back at the box.
- **Settings → Checks** (`src/screens/settings/checks.ts`): `prefs.disabledChecks` (filtered in `run.ts` via `activeFlags`, so off checks neither show nor count) and `prefs.readingTargets` per type (overrides the type file's `readingTarget` in `stats.ts`).
- **Saving:** `flush()` waits for every save already running (two flushes in the same moment, like the timer and a close request, can't let the window close mid-save) and returns false when a save fails. Then the user sees `SAVE_FAILED`, Home/pages stay on the draft, and the first window close is held. Pages outside the flow (guide, practice, settings) remember the paused draft across pages (`app.paused`).
- **Damaged settings files:** `readJson` records files that exist but won't parse in `damagedFiles` (shown in the Home banner), and `writeJson` keeps `<file>.damaged` before writing over one.
- **The app follows its own advice:** `tests/preaches.test.ts` runs the 7 C's checks over every good example, phrase idea, tip, explanation, checklist line, practice situation, and lesson (text in quotes is a "don't" example and is skipped). A new or edited tip that the checks would flag fails the suite.
- **Other screen pieces:** "All steps" outline under the top bar (`src/flow/outline.ts`); Read it aloud (`src/ui/speak.ts`, offline system voices, no button without them); Settings > Writing types saves a copy of a type into `types/` (`src/screens/settings/types.ts`); "Write for your reader" lessons in the guide come from `data/lessons.json`.
- **Web version** (`isWeb` in `src/storage/store.ts`, true only in a `--mode web` build outside Tauri): files live in IndexedDB (`idb-keyval`), Settings swaps Writing types for Backup (`src/storage/backup.ts`, one JSON file of every stored file), Home shows a note that writing stays in this browser, File lists "Save a backup…", Ctrl+N isn't listed (browsers keep it), the status bar says "Spelling loading…" until Harper's 20 MB wasm is ready, and closing the tab with unsaved changes asks first.
- **Zoom** (`src/ui/zoom.ts`, `prefs.zoom`): Ctrl +/-/0. WebView2 never passes these keys to the page, so Windows uses its own zoom (`zoomHotkeysEnabled` in `src-tauri/tauri.windows.conf.json`) and the level is read back as devicePixelRatio ÷ the screen's scale factor; a Mac steps it in `zoom.ts` with `setZoom`. Adding a new platform conf file doesn't make cargo rebuild: touch `tauri.conf.json`.
- **Read it aloud** (`src/ui/speak.ts` → `src/speech/`): the natural voice is Kokoro-82M (fp32) run by kokoro-js on WebGPU in a module worker (`worker.ts`); without a WebGPU adapter, or if it fails, the computer's own voice reads instead. `voices.ts` lists the 6 voices (3 women, 3 men; blends mix Kokoro voice files by weight, done in the worker by replacing `generate_from_ids` with our own style vector). `chunks.ts` cuts text into one sentence per clip and ends each line with a period ("Hi Sam," would rise like a question). Pitch is the AudioBufferSource playback rate; the model speed is divided by it so speed and pitch stay separate (`modelSpeed`). Settings → Voice: voice, speed, pitch (`prefs.voice`, `voiceSpeed`, `voicePitch`). Files: `npm run voice` (`tools/get-voice.mjs`, also run by predev/prebuild) downloads the pinned model + voice files into `voice-pack/` (gitignored, ~314 MB); the desktop bundles it as a Tauri resource read through the asset protocol (`protocol-asset` feature, `assetProtocol.scope`, CSP `asset: http://asset.localhost`); the dev server serves it at `/voice-pack/`; the web version downloads from Hugging Face. The ONNX engine wasm is bundled by Vite with the worker (`wasmPaths` deleted so it never uses the CDN). eSpeak NG inside `phonemizer` is GPL-3.0 (decided 11/02/2026: accept GPL; the app's source must be made available before the next release).
- **Platform differences** live in `src/ui/platform.ts` (`isMac`, `cmdKey`, `keyLabel`). Menu Alt/Option+letter matches `e.code`, not `e.key`, because Option changes the typed character on a Mac.

## Decisions (from 10/28/2026 on)
- Readability is Flesch Reading Ease 0–100, never a school grade level (a grade can feel like an insult). Per-type `readingTarget` (default 60).
- Look: dark OpenOffice-Writer-style layout (menu bar, icon toolbar, the screen as a page on a darker workspace, status bar). Muted green = actions, purple = selection, amber = attention. No blue in the window chrome and no emoji (the Clear check's highlight is still blue, per the brief's 7 C's colors). Colors are tokens at the top of `src/styles/app.css`.
- Coherent hint skips the first paragraph of each body section and looks for linking words only in a paragraph's first sentence.
- Vague-date check skips closing and signature ("Talk soon," is fine).
- Passive voice skips describing words ("I was tired", "is located") from the editable list `data/wordlists/passive-exceptions.json`, unless "by" follows ("was required by law" is still passive). Single letters inside dotted abbreviations ("U.S.", "i.e.") are not slang or a lowercase "i".
- Draft auto-titles include the time, and Home shows a preview line (subject, or first 10 words) so same-day drafts can be told apart.
- `normalizeDraft` replaces any wrong-shaped field (e.g. `"text": "oops"`) with an empty one, so a damaged file can't swallow typing.
- The store refuses Windows device names (`CON`, `NUL`, `COM1`…) and `:` in paths.
- `.docx` is block format for every type (decided 10/29/2026; the old per-type `blockFormat` flag was removed).
- An ALL CAPS run ("PLEASE READ") is Courteous shouting, not Clear acronyms; both use `capsWords()` in `src/checks/text.ts` so they agree.

## Gotchas
- Every source file starts with the two-line Brennan Meyer header; JSON data uses `"_header"`. Tool-owned config JSON has no header: `tauri.conf.json` and capabilities (schema-checked), `package.json`, `package-lock.json`, `tsconfig.json`, `.claude/launch.json`.
- Harper spans are Unicode char indexes; `src/spell/harper.ts` converts to UTF-16.
- The `syllable` package miscounts a few words (e.g. "cooperation" = 4). Use correctly-counted words in hand-checked tests.
- Print sets `@page { margin: 0 }` so the webview can't add its date/title header; the 1" margins come from side padding (both in `src/styles/print.css`) plus repeating table header/footer spacer rows built in `src/export/print.ts`.
- `saveDraft` rolls the saved time back if the write fails, so a failed save never shows "Saved" — keep it that way.
- Python heredocs through the Bash tool mangle `\\` and `\'`; write scripts to the scratchpad, or use the Edit tool.
- The Bash tool runs sandboxed: files it writes under `%APPDATA%` are NOT seen by the installed app. Seed test drafts with the PowerShell tool.
- Computer-use can't see the dev build (not installed); drive it with `WScript.Shell` SendKeys + `snap-window.ps1`, or test the installed build (`C:\Program Files\BEZ Pro Write\`).
- A new GitHub repo may not register a workflow from its very first push; pushing a tag triggered it.
